覆盖记录新增 `consistent`（已对齐）状态（#223 维护者裁决）。

## 问题

覆盖记录的 `COVERAGE_STATUSES` 有五个状态，但**没有一个能表达「已核对且与官方一致」**：

- #165 §4 的处置清单第一项就是「已一致」（六类：已一致 / 修正对齐 / 必要 Vue 适配 /
  本库独立扩展 / 目标版本不适用 / 明确延期）——五档状态装不下这六类里的第一类；
- B/C/D/F 审计表里正有「**已核对且判定为「对齐」（不修，避免无谓改动）**」「**B-A. 判定为对齐**」
  这样的结论，它们没有可落的状态；
- `retained` 明确定义为「有意保留的**差异**」（§3.7），装不下「无差异」。

后果很具体：#165 的收口要求「零未核对」，即 587 个待判名字**每一个**都要有状态 + 依据，
而其中「与官方一致」那一类**无处可落**。

## 改动

- `COVERAGE_STATUSES` 由五档扩为六档，新增 `consistent`，与 §4 的「已一致」对应；
  与 `retained`（有意保留的差异）以**有没有差异**区分。
- `consistent` 与其它已判定档同口径：**必须有非空 `note`**（已对齐同样要留证据，
  否则「全标 consistent」就能把未核对清零 —— 与「全标 retained」是同一个漏洞形态）。
- 文档的「五档处置」改「六档」并加该行；`check:165-coverage` / `generate:165-coverage`
  的统计行加 `consistent`。

## 判据

- `readCoverageRecord`：`consistent` 合法，且**缺 note 抛错**（新增用例）。
- `statusCounts`：新状态被计入（新增用例）。

## 不做

`consistent` 只扩了词汇，不改任何既有判据与记录；存量 1131 条未核对不变。
