# 服务端渲染与生命周期

两件事放在一起讲，因为它们是同一个承诺的两面：**SDK 只在浏览器里活着，而它在浏览器里活多久
不由你的组件说了算。**

## 模块求值期不碰 DOM

`bmap-vue` 的模块顶层**不访问** `window` / `document`。SSR 环境下 `import` 整个包不会崩——
所有真实 DOM 访问都发生在 `onMounted` 之后，或被 `typeof document === "undefined"` 这类
守卫挡在函数内部。

具体到 `<Map>`：组件的 `setup` 会构造内部运行时对象，但**构造过程不访问 DOM**，容器在
`onMounted` 之后才回填、建图只从 `onMounted` 起步。因此服务端渲染出来的 HTML 里只有一个容器
壳（`status` 是 `idle`，渲染 `loading` 插槽的默认文案），**没有任何 SDK 资源**。

模块顶层只有 `typeof` 形态的求值（例如「当前是不是客户端」这种布尔量）。它**不抛**，
因此不构成 SSR 风险；但它读的是模块被 import 那一刻的环境——在**同一进程**里先做 SSR
再接管客户端时（某些同构框架的 dev 模式、进程内测试），这个值不会重算。真实部署里服务端与
浏览器是两个 realm，不受影响。

SSR 期**不会**执行的部分（`onMounted` 不跑）：容器尺寸观察器、页面前后台监听、视口观察、
建图、插件后台加载。

## 容器必须先有尺寸

地图在容器拿到**非零尺寸**之前**不会创建**。这不是保守，是必需的：零尺寸建图在真实浏览器上会
得到一个 0×0 的 WebGL 画布（JSAPI 4.0 不会自己重算尺寸），而 Tab / Drawer / 折叠面板在展开
之前正是 0×0 —— 结果是「地图加载完了但一片空白」。

| 观察点 | 零尺寸期间 | 拿到非零尺寸之后 |
| --- | --- | --- |
| `status` | `idle`（**不进入加载流程**） | `waiting-client` → `creating` / `initializing` → `ready` |
| `#loading` 插槽的 `containerReady` | `false` | `true` |
| `isContainerReady()` | `false` | `true` |
| 地图实例 | 不存在 | 创建一次 |

零尺寸期间 `loading` 插槽的默认文案是 `waiting for container size...`（区分于加载中的
`map loading...`），因为这两件事的处置完全不同：前者要等容器展开，后者要等网络。想自定义
这个文案就用 `#loading` 插槽——它拿到的 `containerReady` 就是这两个状态的判据。

三点补充：

- 尺寸判定读的是**组件根容器**（你声明尺寸的那一层），优先级 `offsetWidth/Height` →
  `clientWidth/Height` → `getBoundingClientRect()`；语义是**布局盒**，所以纯 CSS `transform`
  不算尺寸变化；
- 地图**建好之后**容器再变成 0（折叠 / 切走）**不会销毁地图**，恢复尺寸后由 `checkResize()`
  纠正即可；
- `retry()` 与首次建图共用同一个判据，且一次完整启动是**单飞**的——并发 `retry()` 共享同一次
  启动，不会建出第二张图。容器收起期间 `retry()` 返回的 Promise 保持 **pending**，
  不会拿旧的错误立刻拒绝。

完整口径见[Map 地图](../components/map) 的「容器尺寸、自动重设与可见性策略」。

## 组件卸载：取消等待 ≠ 终止加载

这是本库与上游 Loader 的契约里最容易被误读的一条。

**组件卸载做的是「取消我自己的等待」**：正在等 `ready` 的 Promise 被拒绝，视图的观察器与
订阅被解绑，地图实例与它持有的覆盖物 / 控件 / 图层被释放。

**组件卸载不做的是「终止上游加载」**：官方 Loader **没有公开的取消接口**。因此：

- **不删除**上游注入的 SDK `<script>`，也不**改写**它的 `src` 或属性；
- **不重新插入** `<script>`——同配置的并发消费者共用一份加载任务，后来者复用原任务；
- **不调用官方 `reset()`**。它会把进程级的 `window.BMap` / `BMapGL` 一起删掉，影响的是整个
  页面（乃至整个测试进程），不属于任何单个组件的处置权。官方对它的定位是「便于单测与热更新」，
  不是运行时清理接口；
- **不删改**上游注入的回调全局与命名空间。

全部消费者都离开时，底层任务**保留**（条目、配置占用与在飞任务都留着，直到任务真正成功或
失败），这样「A 组件卸载 → 稍后 B 组件挂载」不会退化成「插两次 script」。单个消费者的取消
只结算它自己：A 取消不会波及同任务上的 B。

这套边界的逐项依据见[官方包发布契约](../contributing/official-packages) 的
「不支持项、易误读项与未验证项」；错误侧的表现是 `BMAP_PROVIDER_ABORTED`
（取消**不是**错误态，组件状态会退回 `idle` 以便重试），见[错误码与排障](./errors)。

## 释放路径

**每一个**监听器、覆盖物、控件、图层、服务结果、Observer、Timer、RAF 与动画都有释放路径，
统一挂在组件的作用域上，卸载即释放：

- 释放顺序是**先断源、再收尾**：先 abort 作用域的 `AbortSignal`（让所有「监听 signal 而非
  监听事件」的在飞工作立刻知道该收手），再按**注册逆序**执行释放函数；
- **一个释放函数抛错不得中断其余释放**——销毁顺序是行为契约，坏掉一个不能连坐；
- 重复释放是 no-op（幂等）。

按资源族看：

| 资源 | 释放时机与口径 |
| --- | --- |
| 地图实例、覆盖物、控件 | 随组件卸载释放；子组件先于父组件卸载，因此子资源能安全问出「整图正在 teardown」 |
| 原生图层（`MarkerCluster` 的 `native` 引擎 + 三个点图层） | 登记进地图的图层账本，**即使地图先被销毁**也会在 `map.destroy()` 之前被摘掉 |
| map 事件订阅 | 绑定在地图实例的资源作用域上；`load` 通过「地图已创建」的挂载点提前订阅，`destroy` 的订阅活到地图销毁那一刻 |
| 尺寸 / 视口 / 页面前后台观察器 | 挂在 `suspension` 控制器上，卸载时一并释放，**不依赖** Vue 组件作用域——「谁释放」只有一个答案 |
| 定时器、RAF、帧调度 | 随作用域 abort 取消；合帧队列保留每个 key 的最后一次 |
| 服务 composable 的结果 | 状态在组件内复位；带实例的服务（本地检索、路线）在失效时终止自有实例 |

组件卸载还会 `emit('unload')`——但要区分：它表示**承载地图的组件**卸载了，不表示整张地图
的 SDK 资源已归零（`<KeepAlive>` 停用是另一条路径，见
[Map 地图](../components/map) 的「KeepAlive」）。**子组件没有 `unload` 事件**。

数据组件另有一条：它们随组件卸载释放全部资源，落在原生图层上的四个还会登记进地图的图层账本，
因此**即使地图先被销毁**，图层也会在 `map.destroy()` 之前被摘掉（这依赖 `<Map>` 提供的
`MapContext.layers`；自定义 Context 没有它时组件退化为自持账本，只保证「组件卸载」这一条路径）。

## `./ui-kit` 必须动态导入

官方 UI Kit 包在**模块求值期**就访问 `document`——在 Node 里 `import` 它会直接崩。因此它是
**独立按需子入口**（`bmap-vue/ui-kit`），并且只满足两条规则：

1. **根入口 `bmap-vue` 不导出那四个组件**，产物里也不含 UI Kit 的代码与样式；
2. **只在浏览器挂载后动态 import 上游包**——`import()` 的 specifier 必须是字面量，打包器才能
   静态分析。

因此在 SSR 项目里：

- 静态 `import` `bmap-vue/ui-kit` **本身是安全的**（这个入口只在浏览器里才碰上游包），但
- **服务端渲染时不要渲染** `PlaceSearch` / `PlaceAutocomplete` / `PlaceDetail` / `RoutePlan`
  这四个组件——在无 DOM 环境调用时会以 `BMAP_UI_KIT_UNAVAILABLE` 明确拒绝并给出可读原因
  （而不是让上游在 import 期崩给你看）；
- 样式**必须由你显式引入**官方 CSS：不引入不会报错，只会「没有样式」，且它是根入口之外的
  一条独立入口。

这四个组件**也不在**组件 manifest 里，因此按需自动导入（resolver）**不会**解析它们——必须显式
写 `import { PlaceSearch } from 'bmap-vue/ui-kit'`。完整用法见[官方 UI Kit 集成](./ui-kit)。

## 排查清单

SSR 项目里遇到 `window is not defined` / `document is not defined` 时，按这个顺序查：

1. 是不是静态引入了 `bmap-vue/ui-kit`（它必须在浏览器挂载后才动态 import 上游包）；
2. 是不是在模块顶层自己 `new` 了 SDK 类的实例——SDK 只在浏览器里存在，顶层构造必然在服务端
   崩；把它挪进 `onMounted`；
3. 是不是在 `bmap-vue` 之外还有别的东西在 import 期碰 DOM（自家地图容器组件、全局样式注入的
   第三方 UI 包）；
4. 容器是不是零尺寸（不是报错，是「一直 `idle`」）——看 `#loading` 插槽的 `containerReady`。

完整错误码见[错误码与排障](./errors)；更多常见问题见 [FAQ](./faq)。
