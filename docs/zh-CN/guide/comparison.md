# 与官方库的关系

百度地图官方也提供 Vue 绑定。这一页说明两个库各自解决什么问题，方便你判断该用哪个。

::: tip 这一页是中立的
本页不比较「谁更快」「谁更全」。性能差异依数据量、渲染路径与机器而变，
在没有同条件实测的情况下断言「A 比 B 快」是没有意义的。
:::

## 两个库

| | [`@baidumap/vue-bmap`](https://www.npmjs.com/package/@baidumap/vue-bmap) | `bmap-vue` |
| --- | --- | --- |
| 定位 | 官方通用 Vue 绑定 | JSAPI 4.0-first、Vue-native |
| SDK 版本 | 3.0 与 4.0 双版本 | **只支持 4.0** | <!-- brand-gate:allow 这里指百度地图 SDK 的引擎版本（上游语义），不是本库的发布版本 -->
| 组件覆盖 | 常用的基础覆盖物与控件 | 覆盖物 / 控件 / 图层 / 批量可视化 / 全景 / 检索 |
| 大数据 | 基础覆盖物为主 | 原生批量图层（线 / 面 / 热力 / 轨迹线）+ 要素状态 + 拾取 |
| 服务 | — | 12 个 headless 服务 composable |
| 维护 | 百度官方 | 社区 |

**选哪个**：需要同时支持 SDK 3.0、或只用到基础覆盖物控件、且希望由官方统一维护， <!-- brand-gate:allow 同上，指上游 SDK 引擎版本 -->
选 `@baidumap/vue-bmap`。已经全面用 4.0、需要大数据渲染、服务能力或生产生命周期保证，
选 `bmap-vue`。

## 命名尽量对齐

两个库的基础 API 命名尽量一致（`Map` / `Marker` / `InfoWindow` / `Polyline` 这类），
方便将来双向迁移。所以从官方库迁过来，或从本库迁回去，模板里的标签名大多不用改。

## 本库不做的事

- **不复用官方做不到的事**：能力矩阵里标 `unsupported` 的就明说不支持，
  不通过访问私有面「补齐」。
- **不复制官方 UI**：建议、结果列表、翻页、详情面板、路线面板、主题都用官方
  `@baidumap/jsapi-ui-kit`，见[官方 UI Kit 集成](./ui-kit)。
- **不自研 SDK 加载**：默认在线加载走官方 `@baidumap/jsapi-loader`。
- **不声称官方不行**：官方库和本库解决的问题范围不同，不存在谁取代谁。

## 互相之间会冲突吗

如果同一个页面里同时用了两个库，它们会各自尝试加载 SDK。
JSAPI 的全局对象是**进程级**的，同一个 realm 里只能存在一份配置——
所以不建议混用。需要迁移时按页面逐步替换，不要在一个页面里同时挂两套。
